# compact-jev Claude Code plugin

This plugin uses Claude Code function hooks to add one slash command,
`/compact-jev [goal]`. It compacts the conversation by removing the tool
calls and tool results Jev judges no longer needed, keeps everything else
verbatim, and adds no summary. It never touches `/compact`, auto-compaction
or any other compaction.

`hooks/compact-jev.ts` is a thin adapter over the library in `src/` (the
plugin folder is the repository root, so the hook imports it directly):

- `session.start` registers `/compact-jev` with `$.command.register`.
- `command.run` on `{ command: "compact-jev" }` marks a run as pending,
  prints `compacting with Jev…`, and schedules `$.session.compact()` with
  `$.clock.after`: the engine refuses that call from inside the command's own
  hook ("it would compact under the turn this hook is holding"). While the
  session is still busy it retries every 500 ms, up to 10 times. The outcome
  is shown as a toast and a log line.
  The text after the command, if any, becomes the `goal` Jev is shown.
- `session.compact` acts only while a run is pending, for the main
  conversation (no `agentId`). It does not check the trigger: on 2.1.280 a
  compaction started from the command's timer arrives as `manual`, not
  `plugin`. Anything outside a pending run goes to `next(event)` untouched.
  If Claude Code compacts without reaching this hook, the command warns that
  the built-in summary ran instead of reporting success.

During a run the hook reads the AI Gateway key, hands the transcript to the
library (which calls `POST https://ai-gateway.vercel.sh/v1/evaluate`, model
`typesafe-ai/jev`, through `$.http.fetch`) and maps the result back onto
session messages. Unchanged messages keep their engine `handle`; rebuilt ones
don't.

- If anything was removed or truncated, it returns `{ messages }`: the pruned
  transcript, with no summary message. There is no minimum-reduction gate.
- If Jev kept everything, it returns `{ skip }`, so the conversation stays as
  it is.
- On any error (missing key, HTTP error, malformed answer, a history too large
  for the state budget), it returns `{ skip }` with the error. Claude Code's
  summarizer is never run in its place.

Per-call probabilities are logged as `decisions:` lines, chunked under 4096
characters.

The plugin is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1

claude plugin marketplace add edoproch/compact-jev
claude plugin install compact-jev@compact-jev
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 AI_GATEWAY_API_KEY=... claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `apiKey` | unset (falls back to `AI_GATEWAY_API_KEY`) |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `model` | `typesafe-ai/jev` |

The key is looked up in this order: the sensitive `apiKey` option,
`AI_GATEWAY_API_KEY` in the process environment, then `env.AI_GATEWAY_API_KEY`
in the merged settings. Prefer the `apiKey` option, since a settings `env`
entry is exported to every Bash child and MCP server.

Every option except `apiKey` and `model` is passed straight to the library;
see the root README for what they do.

## Scope and caveats

- Function hooks are early access and may change between Claude Code
  releases. This plugin uses the generated declarations from 2.1.274 in
  `types/claude-code.d.ts`; regenerate and review that file after a Claude
  Code upgrade.
- The tests drive `register()` against a stand-in engine that, like the real
  one, refuses the first `$.session.compact()` call.
